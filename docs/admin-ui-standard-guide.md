# 어드민 표준 UI 가이드 — 화면 패턴 정의
                                                                                
- 작성일: 2026-10-02
- 버전: 0.1
- 상태: 요구조건 반영 초안
- 문서 범위: 화면 패턴 유형, MDI 화면 구조, 공통 기능, 처리 상태 및 예외
- 작성 기준: 현재 대화에서 정의한 내용. 제안 정책은 확정 요구사항과 구분한다.

## 1. 목적 및 대상 사용자

업무 특성에 맞는 화면 패턴을 정의하여 사용자에게 일관된 조작 방식을 제공하고, 기획·디자인·개발 시 반복되는 설계 판단을 줄인다.

| 대상 사용자 | 활용 목적 |
|---|---|
| 운영 담당자 | 데이터 조회 및 업무 처리 |
| 시스템 관리자 | 사용자·권한·기준정보 관리 |
| 기획자·디자이너·개발자 | 공통 기준으로 화면 설계 및 구현 |

## 2. 확정된 적용 범위

| 구분 | 확정 내용 |
|---|---|
| 화면 환경 | PC 전용 |
| 업무 범위 | 조회·관리·결재·승인·일괄 지급 |
| 화면 체계 | MDI 탭 방식 |
| 공통 기능 | 엑셀 다운로드·업로드, 변경이력, 결재를 전체 범위에 적용 |
| 구축 방식 | 신규 구축. 기존 디자인 시스템 및 공통 컴포넌트 없음 |

**해석 제안:** 공통 기능은 모든 화면에서 활용할 수 있는 공통 규격으로 구축한다. 개별 화면에서의 노출 및 사용 여부는 업무 대상, 사용자 권한, 처리 상태에 따라 결정한다. 이는 “전체 적용”의 구현 방식에 대한 제안이며 추가 확정이 필요하다.

## 3. 화면 패턴 유형 — 제안

패턴은 화면 모양보다 사용자의 중심 업무를 기준으로 선택한다. 아래 분류 및 ID는 제안이며 실제 메뉴와 대조하여 확정한다.

| ID | 패턴 | 기본 구성 | 적용 예 |
|---|---|---|---|
| PT-01 | 목록 조회형 | 검색 조건 → 결과 목록 → 페이지 이동 | 지급내역·처리이력 조회 |
| PT-02 | 상세 조회형 | 식별 정보 → 상세 정보 → 관련 내역 | 지급 건 상세 조회 |
| PT-03 | 등록·수정형 | 입력 항목 → 검증 → 저장·취소 | 기준정보 등록 |
| PT-04 | 목록·상세형 | 목록 + 선택 대상의 상세·편집 | 사용자 그룹 관리 |
| PT-05 | 계층 관리형 | 트리 + 선택 대상의 상세·편집 | 메뉴·조직 관리 |
| PT-06 | 관계 설정형 | 기준 대상 + 연결 대상 + 배정·해제 | 그룹별 사용자·권한 설정 |
| PT-07 | 일괄 처리형 | 대상 조회 → 다중 선택 → 실행 확인 → 건별 결과 | 일괄 상태 변경 |
| PT-08 | 단계 진행형 | 단계 표시 → 단계별 처리 → 최종 확인 | 파일 업로드·검증·반영 |
| PT-09 | 대시보드형 | 주요 지표 → 처리 필요 항목 → 업무 이동 | 운영 현황 |
| PT-10 | 결재·승인 처리형 | 대상 목록 → 업무 상세 → 결재정보 → 승인·반려 | 결재함·승인함 |
| PT-11 | 일괄 지급형 | 대상 산출·조회 → 검증 → 지급 확정 → 실행 → 결과 | 리워드 일괄 지급 |

### 3.1 패턴 선택 기준

| 주된 업무 | 적용 패턴 |
|---|---|
| 여러 건을 찾거나 비교 | 목록 조회형 |
| 한 건의 정보 확인 | 상세 조회형 |
| 데이터 작성 및 수정 | 등록·수정형 |
| 목록의 대상을 바꾸며 상세 확인 및 편집 | 목록·상세형 |
| 상하위 구조 유지 및 관리 | 계층 관리형 |
| 두 대상 사이의 소속·배정 관계 설정 | 관계 설정형 |
| 여러 건에 동일 명령 적용 | 일괄 처리형 |
| 선행 조건에 따라 순차 진행 | 단계 진행형 |
| 전체 현황 및 우선 처리 대상 파악 | 대시보드형 |
| 결재 대상의 업무 내용을 검토하고 승인·반려 | 결재·승인 처리형 |
| 지급 대상 검증 및 실제 일괄 지급 | 일괄 지급형 |

화면별 주 패턴 1개를 지정하고 필요한 보조 구성을 추가하는 것을 제안한다. PT-10과 PT-11은 처리 정책의 중요성을 반영한 업무 특화 패턴이며, 실제 배치는 목록·상세형이나 단계 진행형 등을 활용할 수 있다.

탭·팝업·아코디언은 독립 업무 패턴이 아니라 패턴 안에서 사용하는 구성 요소로 정의한다. 변경이력 팝업, 결재 탭, 엑셀 업로드 창은 공통 구성으로 추가한다.

## 4. MDI 공통 화면 구조 — 제안

| 영역 | 표준 구성 | 설계 기준 |
|---|---|---|
| 상단 | 시스템명·사용자·공통 메뉴 | 모든 업무 화면에서 유지 |
| 좌측 | 업무 메뉴 | 접기·펼치기 제공 |
| MDI 탭 | 열린 화면명·활성 표시·닫기 | 동일 화면의 중복 열기 기준 정의 |
| 화면 제목 | 화면명·관련 공통 기능 | 기능 배치 및 순서 통일 |
| 업무 영역 | 검색·목록·상세·입력 | 선택한 화면 패턴 적용 |
| 업무 버튼 | 저장·결재요청·승인·지급 등 | 현재 상태에서 가능한 행위만 활성화 |

### 4.1 탭 동작

- 검색 조건, 페이지, 선택 항목, 수정 내용을 탭별로 유지한다.
- 저장하지 않은 입력이 있는 탭을 닫거나 다른 대상으로 이동할 때 확인을 제공한다.
- 변경이 없으면 추가 확인 없이 이동한다.
- 최대 탭 수, 동일 화면 중복 열기, 서로 다른 상세 건의 탭 구성 방식은 미확정이다.

## 5. 공통 UI 정책 — 제안

| 항목 | 표준 정책 | 예외 처리 |
|---|---|---|
| 화면 구성 순서 | 제목 → 검색/업무 영역 → 결과/상세 영역 | 검색이 불필요하면 검색 영역 생략 |
| 목록·상세 배치 | 목록 식별 항목과 상세 정보량을 고려해 좌우 또는 상하 배치 | 공간 부족 시 별도 상세 화면 제공 |
| 최초 조회 | 조회 범위가 명확하고 데이터량이 제한적이면 자동 조회 | 대량 데이터는 필수 검색 조건 입력 후 조회 |
| 목록 선택 | 선택 대상을 명확히 표시 | 미선택 시 상세 영역에 선택 안내 |
| 저장 검증 | 오류 위치와 수정 방법 표시 | 여러 오류가 있으면 첫 오류로 이동할 수 있도록 제공 |
| 일괄 처리 | 실행 전 대상 건수와 작업 내용 확인 | 일부 실패 시 성공·실패 건 구분 |
| 권한 | 조회·등록·수정·삭제 등 행위별 권한 적용 | 서버에서도 권한 없는 요청 차단 |
| 빈 결과 | 데이터 없음과 검색 결과 없음 구분 | 조회 실패는 오류 안내 및 재시도 제공 |
| 팝업 | 짧은 확인·선택·보조 작업에 사용 | 복잡한 입력 및 장시간 작업은 별도 화면 제공 |

## 6. 공통 업무 기능 — 제안

| 기능 | 공통 흐름 | 필수 정책 |
|---|---|---|
| 엑셀 다운로드 | 범위 선택 → 다운로드 | 조회 결과/선택 건 구분, 권한·개인정보·최대 건수 |
| 엑셀 업로드 | 양식 확인 → 파일 선택 → 검증 → 결과 확인 → 반영 | 오류 행 제공, 중복 기준, 전체/부분 반영 기준 |
| 변경이력 | 대상 식별 → 변경 목록 → 변경 전후 비교 | 변경자·일시·항목·전후 값, 민감정보 표시 기준 |
| 결재 | 업무 저장 → 결재자 지정 → 요청 → 검토 → 승인·반려 | 결재 단계, 자가결재, 회수, 승인 후 수정 기준 |

변경이력은 데이터 변경 기록, 결재이력은 요청·승인·반려 등 의사결정 기록으로 구분한다. 진입 위치를 연결할 수 있으나 기록 목적과 항목은 각각 정의한다.

## 7. 처리 상태와 예외 — 제안

아래 상태는 개념 흐름이며 확정된 상태 코드가 아니다. 실제 상태 전이와 버튼 규칙은 업무 정책 확정 후 상세화한다.

| 업무 | 제안 상태 흐름 | 주요 예외 |
|---|---|---|
| 결재 | 작성 → 요청 → 검토 중 → 승인/반려 | 회수, 결재자 부재, 수정 후 재요청 |
| 일괄 지급 | 대상 준비 → 검증 완료 → 지급 가능 → 처리 중 → 완료/부분 실패/실패 | 중복 지급, 한도 초과, 대상 변경, 결과 미확정 |
| 엑셀 업로드 | 파일 선택 → 검증 → 반영 가능 → 반영 중 → 완료/실패 | 양식 오류, 중복, 일부 행 오류, 반영 중 장애 |

### 7.1 결재

- 결재 단계 및 결재자 지정 방식을 정의한다.
- 자가결재, 회수, 반려 후 수정·재요청, 승인 후 수정 가능 여부는 미확정이다.
- 상태에 따라 가능한 업무 버튼을 제어한다.

### 7.2 일괄 지급

- 결재가 필요한 지급 업무는 승인 완료를 지급 가능 조건에 포함한다. 적용 여부는 미확정이다.
- 지급 요청 후 응답이 끊긴 건은 결과 확인 전 재지급하지 않도록 설계한다.
- 부분 실패 시 성공 건과 실패 건을 분리한다.
- 재처리 대상은 기존 처리 결과 확인 후 결정한다.
- 중복 지급, 한도 초과, 검증 후 대상 변경에 대한 처리 기준은 상세 확정이 필요하다.

### 7.3 엑셀 업로드

- 검증 결과를 확인한 뒤 반영한다.
- 오류 행, 중복 데이터 및 반영 중 장애에 대한 결과를 제공한다.
- 전체 반영 또는 유효 행만 부분 반영할지는 미확정이다.

## 8. 신규 공통 컴포넌트 — 제안

| 구분 | 주요 컴포넌트 |

| 화면 틀 | 메뉴·MDI 탭·화면 제목·분할 영역 |

| 업무 처리 | 버튼 영역·상태 표시·실행 확인·처리 결과 |
| 공통 업무 | 엑셀 업로드·변경이력·결재정보·결재자 선택 |
| 피드백 | 로딩·빈 결과·오류·성공 알림 |

## 9. 미확정 사항

| 구분 | 추가 확정 항목 |
|---|---|
| MDI | 최대 탭 수, 중복 열기, 상세 건별 탭 구성 |
| 공통 기능 적용 | 화면별 기능 노출 및 사용 조건 |
| 결재 | 단계, 자가결재, 회수, 결재자 부재, 승인 후 수정 |
| 지급 | 승인 필요 여부, 한도·중복 검증, 결과 미확정 및 재처리 |
| 엑셀 | 다운로드 범위·최대 건수·개인정보, 중복 및 부분 반영 |
| 화면 상세 기준 | 기준 해상도, 영역 크기, 색상·타이포그래피·간격 |
| 패턴 적용 | 실제 메뉴별 주 패턴 및 보조 구성 매핑 |

## 10. 후속 설계

1. 미확정 정책을 결정한다.
2. 실제 메뉴별 주 패턴 및 공통 기능 적용 여부를 매핑한다.
3. 패턴별 영역 배치와 버튼·상태 규칙을 상세화한다.
4. 공통 컴포넌트 규격을 정의하고 개별 화면설계서에 연결한다.

현재 문서는 화면 패턴 중심의 초안이다. 상세 화면설계서와 디자인 시스템 수치 규격은 포함하지 않는다.
